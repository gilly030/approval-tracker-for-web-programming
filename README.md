# 대통령 직무평가 트래커

한국갤럽 데일리 오피니언 PDF에서 **대통령 직무 수행 평가의 응답자 특성별 표**를 뽑아,
배너(지역·성·연령·지지정당·직업·이념성향 등)를 골라 볼 수 있게 보여주는 정적 사이트입니다.
HTML·CSS·JavaScript만 씁니다. 서버나 빌드 도구가 필요 없습니다.

```
index.html          공개 페이지 (외부 라이브러리 없음, 차트는 SVG로 직접 그림)
admin.html          관리자 페이지: PDF를 올려 data.json에 반영
css/style.css
js/app.js           공개 페이지 로직
js/linechart.js     Gallup 리포트식 선 그래프 (범례 강조, 점 주석, 데이터·이미지 내보내기)
js/admin.js         관리자 페이지 로직 (pdf.js를 CDN에서 불러옴)
js/parser.js        PDF → 표 추출기 (브라우저·Node 공용)
js/normalize.js     시기마다 다른 배너·그룹 이름을 하나로 묶는 표
js/merge.js         추출 결과를 data.json에 병합
data/data.json      사이트가 읽는 데이터
data/state.json     자동 갱신이 어디까지 처리했는지 기록
tools/update.mjs    자동 갱신 스크립트 (GitHub Actions에서 실행)
tools/parse-node.mjs  (선택) 같은 파서를 Node에서 돌리는 명령줄 도구
.github/workflows/update.yml  매일 두 번 자동 갱신
```

## 자동 갱신 (기본)

`.github/workflows/update.yml`이 매일 두 번(한국시간 11:23, 19:23) 실행됩니다.

1. 갤럽 리포트 게시판에서 가장 큰 게시물 번호를 확인합니다.
2. `data/state.json`의 `lastSeq`보다 큰 번호의 PDF를 받아 파싱하고 `data/data.json`에 반영합니다.
3. `state.backfill`이 끝나지 않았으면 과거 번호로 내려가며 한 번에 최대 40개씩 채웁니다. 2025년 6월 이전 리포트를 만나면 멈춥니다.
4. 데이터가 바뀌었을 때만 커밋하고 GitHub Pages를 다시 배포합니다.

바로 돌려보려면 저장소의 **Actions → 갤럽 리포트 자동 반영 → Run workflow**를 누르세요. 실행 기록에 받은 리포트와 경고가 남습니다.
게시판 구조가 바뀌어 번호를 못 찾으면 실행이 실패로 표시되고, GitHub이 저장소 주인에게 메일을 보냅니다.

## 수동 반영 (자동 갱신이 막혔을 때)

1. 갤럽 리포트 게시판에서 새 "데일리 오피니언" PDF를 받습니다.
2. `admin.html`을 열고 PDF를 끌어다 놓습니다.
3. 카드마다 나오는 검증 결과를 확인합니다.
   - **검증 통과**: 모든 행의 비율 합이 100±2%이고 빈 칸이 없음
   - **확인 필요**: PDF 원문과 한 번 대조할 행이 있음 (예: 칸 하나가 비어 있음)
   - **참고(사례수 합계)**: 그룹 사례수 합이 전체와 다름. 지지정당별은 주요 정당만, 생활수준별은 '모름'을 빼고 싣기 때문에 보통 정상입니다.
   - **(새 이름)**: `normalize.js`에 없는 배너 이름. 그대로 써도 되고, 기존 배너와 같은 것이면 `normalize.js`에 한 줄 추가하세요.
4. "선택한 조사 반영" → "data.json 내려받기" → 사이트의 `data/data.json`에 덮어씁니다.

정적 호스팅(GitHub Pages, Netlify 등)은 브라우저가 서버 파일을 직접 고칠 수 없어서 마지막 단계는 파일을 바꿔 올리는 방식입니다.
`admin.html`은 공개해도 데이터가 바뀌지는 않지만, 원치 않으면 배포 대상에서 빼세요.

## 로컬에서 열기

ES 모듈과 `fetch`를 쓰기 때문에 파일을 더블클릭(file://)하면 동작하지 않습니다. 폴더에서:

```
npx serve .        # 또는 python3 -m http.server
```

## 파서가 표를 찾는 방법

배너나 열 구성을 코드에 고정하지 않았습니다. 2012~2026년 리포트 7개로 확인한 형식 차이를 모두 이 규칙으로 처리합니다.

- **기준점**: 오른쪽에 숫자가 이어지는 '전체' 행. 한 쪽에 표가 두 개 나란히 있어도(월간 통합) 각각 찾습니다.
- **대상 표**: 머리글에 '대통령'과 '직무'가 있고 '당선인'은 없는 표만 씁니다. 정당 지지도, 국회 평가 같은 표는 건너뜁니다.
- **열**: 값의 오른쪽 끝 좌표로 열을 묶고, 그 위에 쌓인 머리글 글자로 이름을 읽습니다. '잘하고' 열부터 '전체' 행 합이 100%가 될 때까지가 평가 열입니다. 그래서 2012년처럼 정당 지지도 열이 바로 옆에 붙어 있어도 거기서 멈춥니다. 그 뒤에 직전 열을 쪼갠 열(의견유보 = 어느 쪽도 아님 + 모름)이 있으면 세부 값으로 저장합니다.
- **배너**: 그룹 이름보다 왼쪽에 있는 글자입니다. '주요 / 지지 / 정당별'처럼 여러 줄로 나뉜 것을 이어 붙이고, '…별'로 끝나면 끊습니다. 그룹 첫 줄에 있든(2013~), 그룹 가운데에 있든(2012) 처리합니다.
- **미공개 칸**: 표본이 적어 '-'로 표시된 그룹은 `null`로 저장하고 화면에는 '미공개'로 보여줍니다.

| 시기 | 사례수 열 | 평가 열 | 배너 위치 |
|---|---|---|---|
| 2012 | 1개 | 잘함 / 잘못 / 보통 / 모름 (% 기호 없음) | 그룹 세로 가운데 |
| 2013 | 1개 | 잘함 / 잘못 / 보통이다·어느 쪽도 / 의견유보·모름 | 그룹 첫 줄 |
| 2026 | 2개 (조사완료·가중적용) | 잘함 / 잘못 / 의견유보 (+세부 2열) | 그룹 첫 줄 |

## data.json 구조

```json
{
  "updated": "2026-11-09",
  "surveys": [{
    "key": "2026-11-W1", "type": "weekly", "year": 2026, "month": 11, "week": 1,
    "label": "2026년 11월 1주 (3~5일)", "president": "이재명", "issue": 681,
    "columns": { "n": ["사례수","가중적용 사례수"], "main": ["잘하고 있다","잘못하고 있다","의견유보"], "detail": ["어느 쪽도 아님","모름/응답거절"] },
    "rows": [
      { "banner": "연령별", "group": "29세 이하", "raw": "연령별|18~29세",
        "n": 145, "nWeighted": 146, "pos": 28, "neg": 49, "rest": 22,
        "detail": { "어느 쪽도 아님": 3, "모름/응답거절": 19 } }
    ]
  }]
}
```

- 주간 조사 키는 `YYYY-MM-W주`, 월간 통합은 `YYYY-MM-M`입니다.
- 월간 통합 표는 매달 마지막 주 리포트에 그해 1월부터 다시 실립니다. 그래서 한 개만 올려도 그해 월별 추이가 채워집니다.
- `raw`는 이름을 정규화했을 때만 붙고, 원래 표기를 담습니다.

## (선택) Node로 한꺼번에 처리

과거 PDF를 여러 개 한 번에 넣을 때 편합니다.

```
npm install pdfjs-dist@4.10.38
node tools/parse-node.mjs 리포트들/*.pdf -v --merge data/data.json
```

`-v`를 붙이면 모든 행을 출력합니다. 같은 스크립트에 갤럽 게시판 확인과 PDF 다운로드를 붙이면 GitHub Actions에서 하루 한 번 자동으로 돌릴 수도 있습니다. 서버 쪽 요청에는 CORS 제한이 없습니다.
